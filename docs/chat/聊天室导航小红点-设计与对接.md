## 1. 背景与目标
- 现状：导航栏的小红点已覆盖“文章/题目/课程章节”的列表级未读（以频道 `ReadChannel` + `UserLastSeen` 统计）。
- 诉求：在“聊天室”导航上也显示小红点，但仅对“用户加入的房间”中产生的新消息生效（且排除用户自己发送）。
- 拍板：采用方案A（按房间未读聚合），导航红点严格表示“是否仍存在任一房间的未读消息”。
- 不做：逐条消息已读表；以房间维度的 Last Seen 聚合为主。

## 2. 口径与数据源（方案A）
- 数据口径：
  - 用户加入的房间集合 R；
  - 对每个房间 rid ∈ R，取 `lastSeenAt(user, rid)`；
  - 统计 `create_time > lastSeenAt(user, rid)` 且 `sender_id != userId` 的消息条数；
  - 导航红点根据“是否存在未读（>0）”显示，或展示汇总总数。
- 现有支撑能力：
  - 房间 lastSeen：`ChatRoomReadDomainService`（user×room 维度，表 `user_chat_room_last_seen`）。
  - 批量未读统计：`ChatMessageDomainService#countUnreadByRoomsForUser(roomIds, lastSeens, userId)`（含最小阈值优化）。
  - 判定已加入房间：`ChatRoomDomainService#getJoinedRoomIds(userId, roomIds)`（已支持对一组房间判定；本方案将补充“列出用户全部已加入房间ID”的接口）。

首次策略（建议并落地）：
- 为避免“刚加入就把历史消息算作未读”，在“加入房间”成功后，立即调用 `ChatRoomReadDomainService.updateLastSeen(userId, roomId, now)` 将该房间的 lastSeen 初始化为当前时间（见 §6 落地改动1）。

## 3. 方案拍板
- 采用方案A：按房间未读聚合，导航红点严格表示“仍有未读消息”。
- 清零时机：进入具体房间并调用 `PUT /api/app/chat-rooms/{roomId}/visit` 后，该房间未读清零。
- 可选增强：“全部已读”接口见 §4.3（方便用户一键清空导航红点）。

## 4. 接口与返回结构（导航聚合）
- 推荐复用“未读汇总”接口，新增字段 `chatsUnread`：
  - `GET /api/user/unread/summary`
  - 响应示例：
    ```json
    {
      "code": 200,
      "message": "success",
      "data": {
        "postsUnread": 3,
        "questionsUnread": 0,
        "chaptersUnread": 5,
        "chatsUnread": 2
      }
    }
    ```
- 字段含义：
  - `chatsUnread` 为“加入的房间未读消息总数”（排除自己发送）。前端一般仅据 `> 0` 显示红点，数字可做 `99+` 上限。

可选：如需解耦，也可提供 `GET /api/app/chat-rooms/unread-total`（返回 `{ total: number }`），但优先推荐统一汇总。

### 4.1 房间内清零（已存在）
- `PUT /api/app/chat-rooms/{roomId}/visit`
- 语义：把该房间 lastSeen 推进到 `serverNow`（或带锚点的时间，详见现有实现）。

### 4.2 全部清零（可选新增）
- `PUT /api/app/chat-rooms/visit-all`
- 语义：将“用户已加入的全部房间”的 lastSeen 统一推进到 `serverNow`。仅在确有交互需要时再实现。

## 5. 后端编排与落位（DDD）
- Application（编排）：`UnreadAppService`
  - 新增对“聊天室未读”的聚合逻辑：
    1) 获取该用户“已加入的房间ID集合”（新增 `ChatRoomDomainService#listJoinedRoomIdsByUser(userId)` 或在现有分页列表中缓存/透传）；
    2) 批量读取房间 lastSeen：`ChatRoomReadDomainService#getLastSeenForRooms(userId, roomIds)`；
    3) 批量统计未读：`ChatMessageDomainService#countUnreadByRoomsForUser(roomIds, lastSeens, userId)`；
    4) 汇总为 `chatsUnread = sum(roomUnread[roomId])`；
    5) 通过 `UnreadAssembler` 回填到 `UnreadSummaryDTO`。
- Domain（规则）：
  - 不涉及 Controller/UserContext；仅完成“是否加入”“lastSeen 读取/更新”“按时间窗计数”的业务规则。
- DTO/Assembler：
  - `UnreadSummaryDTO` 新增 `private Long chatsUnread;`
  - `UnreadAssembler#toDTO(...)` 追加该字段，默认空值→0。

参考伪代码（App层聚合）：
```java
// UnreadAppService#getUnreadSummary(userId)
Set<String> roomIds = chatRoomDomainService.listJoinedRoomIdsByUser(userId);
Map<String, LocalDateTime> lastSeens = chatRoomReadDomainService.getLastSeenForRooms(userId, roomIds);
Map<String, Long> unreadMap = chatMessageDomainService.countUnreadByRoomsForUser(roomIds, lastSeens, userId);
long chatsUnread = unreadMap.values().stream().mapToLong(v -> v == null ? 0L : v).sum();
```

## 6. 落地改动清单（最小改动集）
1) DTO：为 `UnreadSummaryDTO` 增加字段 `chatsUnread`；`UnreadAssembler` 对应追加，空值→0。
2) App：在 `UnreadAppService#getUnreadSummary(userId)` 中，增加“聊天室未读聚合”编排，填充 `chatsUnread`。
3) Domain：为 `ChatRoomDomainService` 增加 `listJoinedRoomIdsByUser(String userId)`（从成员表一次性查出用户已加入的 roomId 集合）。
4) Join初始化：在“加入房间”成功后（`ChatRoomAppService.joinRoom` 或 Domain 内部），调用 `chatRoomReadDomainService.updateLastSeen(userId, roomId, LocalDateTime.now())` 初始化 lastSeen，以避免把历史消息计作未读。
5) 可选接口：新增 `PUT /api/app/chat-rooms/visit-all`（如产品确认需要）。

## 7. 前端对接建议
- 导航加载/轮询：继续调用 `/api/user/unread/summary`，读取 `chatsUnread`。
- 显示策略：`chatsUnread > 0` 则显示红点（可做 `99+` 上限）。
- 清零策略：
  - 进入具体房间后调用 `PUT /api/app/chat-rooms/{roomId}/visit`；如增加“全部已读”，在聊天室首页提供入口。

## 8. 性能评估
- 查询路径（方案A，单次汇总）：
  1) 获取已加入房间ID集合（可通过成员表一次查询）；
  2) 批量读取这些房间的 lastSeen（一次查询）；
  3) 以“最小 lastSeen”为阈值批量扫描消息并在内存分发计数（已有实现）；
  4) O(房间数 + 命中消息数) 级别开销。
- 索引：`chat_messages(room_id, create_time)`、`user_chat_room_last_seen(user_id, room_id)` 唯一索引已具备。
- 限制：同屏房间数有限；如需进一步降载，可缓存 `chatsUnread` 短期值或只返回 `exists` 布尔（存在未读即 true）。

## 9. 边界与一致性
- 仅统计“用户加入”的房间；非成员无权计数/清零。
- 排除用户本人发送的消息。
- `create_time > lastSeenAt` 作为严格比较（避免等于边界重复计数）。
- 防回拨：`updateLastSeen` 仅允许向前推进（领域服务已实现）。
- 首次策略：采用“加入后初始化为 now”；如需把历史消息也计作未读，可移除此初始化。

## 10. 回归与兼容
- 向后兼容：`/api/user/unread/summary` 返回体新增字段，不影响旧前端（忽略未知字段）。
- 仅新增读取与汇总逻辑，不涉及存量数据迁移；“加入即初始化 lastSeen”为新增行为，幂等安全。

## 11. 验收清单（QA）
- [ ] 用户未加入任何房间时，`chatsUnread=0`，不显示红点。
- [ ] 用户加入房间A，其他人发消息后，`chatsUnread>0`。
- [ ] 用户自己发消息不计入 `chatsUnread`。
- [ ] 进入房间A后调用 `visit`，房间A未读清零；若仍有房间B未读，导航红点继续存在（方案A）。
- [ ] 并发/重复 `visit` 不回拨；同一时间点边界不重计。
